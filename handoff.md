# nefor-dash — Handoff

Pixel-perfect вёрстка дашбордов Альфа-Бизнеса, мигрированная со статики на **Next.js 15**.
Цель проекта — точная вёрстка и «живые» анимации; при миграции всё сохранено 1:1.

## Стек

- **Next.js 15.5** (App Router) · **React 19** · **TypeScript 5.9**
- Без UI-библиотек. Глобальный CSS (перенесён вербатим из исходной статики).
- Шрифты — локальные woff2 (`Alfa Interface Sans`, `Styrene UI`).
- Деплой — **Vercel** из ветки `main` (фреймворк определяется автоматически).

## Запуск

```bash
npm install
npm run dev        # dev-сервер (по умолчанию :3000; в проекте использовался -p 8734)
npm run build      # прод-сборка (проверка типов). НЕ запускать при живом dev — см. «Подводные камни»
npm start          # прод-сервер после build
```

## Роуты

| URL         | Что это |
|-------------|---------|
| `/`         | Главная. Внутри — переключаемые варианты **v1** и **v2** (тоггл в панели tools, НЕ отдельный роут) |

## Как перенесена вёрстка (важно!)

Крупная статичная разметка (сайдбары, контент, Spotlight, твикер) перенесена **байт-в-байт**
из оригинальных HTML через `dangerouslySetInnerHTML`, а не переписана вручную в JSX. Строки
лежат в `components/dashboard/htmlPartials.ts`, сгенерированы скриптом
`scratchpad/extract.py` (нормализует пути ассетов `../assets|assets → /assets`). Это
гарантировало пиксель-перфект и целостность анимаций. Поведение навешивается типизированными
хуками, которые опрашивают DOM (`document.querySelector`) в `useEffect` с полным cleanup —
как в исходных vanilla-скриптах.

> Если правите статичную разметку — правьте оригиналы и перегенерируйте `htmlPartials.ts`,
> либо (проще для мелочей) редактируйте строки в `htmlPartials.ts` напрямую. Со временем
> имеет смысл поэтапно переписать партиалы в настоящий JSX.

## CSS

- `styles/easter.css` (кирка + РПГ) и `styles/td.css` («Защита счёта») — НОВОЕ, к
  исходной статике отношения не имеют; оба грузит `ToolsProvider`.
- Все 6 файлов в `styles/` перенесены **вербатим** (правились только `url()` → `/assets`,`/fonts`).
- `menu2.css` грузится **глобально** (в layout): его правила сайдбара скоуплены под `.v2`/`.m2-*`

- `styles/tools.css` — только НОВОЕ (карточки-селектор, сегмент v1/v2, рамка-обрезка).

## Панель tools

Живёт в **root layout** (`ToolsProvider` → `ToolsPanel`), поэтому **переживает смену роута**.

- **Селектор дашбордов** (карточки «Предприниматель» = Главная, «Бухгалтер» = Current) —
  клик делает `router.push` (клиентская навигация): контент и тело панели подменяются,
  **панель не закрывается** (бесшовный своп).
- **Тоггл v1/v2** (только на Главной) — меняет `variant` в контексте, без смены роута.
- **Параметры v2** — 6 свитчей стека счетов; двигают сайдбар через контекст → `useV2Page`.
- Открывается/закрывается FAB; **закрывается по Esc**.
- **Рамка:** при открытии вьюпорт дашборда ОБРЕЗАЕТСЯ через `clip-path` (содержимое 1:1, НЕ
  масштабируется; лишнее по краям отсекается), вокруг — чёрный фон на `html`. Отступы 12px,
  справа 332 (панель 320 + зазор 12).

Состояние контекста: `dashboard` (из pathname), `variant`, `v2State` (6 булей), `panelOpen`.

## Neuro-модуль

`NeuroBar` (умная строка снизу) на v2 и `/current`. Клик → разворот пилюли (магнит к
курсору), Enter/лупа → фуллскрин-чат с «мышлением» и blur-стримингом захардкоженного ответа.
Esc-цепочка: чат → Spotlight → сворачивание строки. Весь моушен — порт 1:1 из `js/neuro-bar.js`.

## Пасхалки

Вход — клавиша **«6», затем «7»** в течение секунды (только на Главной). Панель tools
подменяется «инвентарём» на три слота; выход — та же пара клавиш или перезагрузка,
мир дашборда восстанавливается полностью.

| Слот | Что делает |
|------|------------|
| Кирка | Баннеры добываются как блоки: зажать мышь, трещины, разлёт частиц |
| Меч | Пошаговый РПГ-бой «Продукт» против босса «Продажи» (скиллы Q/W/E/R/F) |
| Турель | **«Защита счёта»** — киберпанк tower defence поверх дашборда |

### «Защита счёта» (`useTowers.ts` + `components/easter/td/`)

Дашборд становится ночным кварталом: **карточки вёрстки — крыши**, на них ставятся
башни; **зазоры между карточками — улицы**, по ним к балансу в сайдбаре бегут списания.
Прорвавшийся враг **списывает деньги с настоящей плашки `.sb-amt`** — ноль на счету
означает поражение; на выходе исходное значение возвращается.

- `pixel.ts` — мини-язык пиксель-арта (rect/ellipse/line/pixel → буфер индексов →
  авто-обводка → запекание в offscreen). Плюс `pxLine`/`pxDot` для того, что рисуется
  в кадре: повёрнутые стволы, молнии, трассеры.
- `art.ts` — спрайты: 5 башен (основание + ствол, который движок доворачивает к цели)
  и 5 врагов по два кадра ходьбы.
- `field.ts` — **поле собирается из `getBoundingClientRect` живого DOM**: список
  селекторов-«зданий», сетка 20px, Дейкстра от ядра с надбавкой за клетки впритык к
  стене (иначе путь липнет к углам), до трёх точек входа у правого края, сглаживание
  Чайкиным. Зоны HUD, колоды и бестиария вырезаются из поля отдельным списком.

  **Три дорожки — по одной на коридор вёрстки** (`laneRows`): над чипсами,
  между чипсами и баннерами, под баннерами. Просто «войти на нужной высоте»
  мало: справа от контента вся колонка свободна, и Дейкстра от нижнего входа
  сразу уводит путь наверх — там короче. Поэтому маршрут собирается из двух
  отрезков через **путевую точку** в середине своего коридора: вход → точка →
  ядро (`runDijkstra` принимает стартовую клетку, `descend` спускается по
  градиенту). Именно это держит дорожку в её улице.

  Дальше путь доводится до прямых линий в три приёма — и **каждый отрезок
  обрабатывается отдельно**, иначе нить стягивает прогон и подъём к ядру в одну
  наклонную через весь экран и поворот пропадает:
  1. `stringPull` — убираем точки, между которыми есть прямая видимость (с
     запасом по обочинам): Дейкстра ходит по клеткам и вдоль коридора выдаёт
     лесенку, здесь от неё остаются только настоящие повороты;
  2. `axisSnap` — почти горизонтальные отрезки прижимаются к одной высоте,
     почти вертикальные к одной абсциссе (со сверкой, что прямая осталась
     свободной), затем совпавшие по направлению сливаются;
  3. `roundCorners` — скругляются **только углы**, а не весь путь: прежнее
     сглаживание Чайкиным тянуло к кривой каждую точку и превращало дорожку в
     сплошную дугу.
  **Строить можно только на трёх баннерах и четырёх чипсах** (`ROOF_SEL =
  ".banners > .banner, .chips .chip"`): остальные блоки остаются зданиями и
  формируют улицы, но крышами не считаются.
  **Места под башни замощены ВНУТРИ каждой крыши**, от её собственного угла, а
  не по общей сетке экрана. Это принципиально: `.content` имеет `width:960;
  margin:0 auto`, поэтому на широком окне он центрируется и карточки встают на
  некратные 40 координаты — при экранной сетке квадраты постройки визуально
  «съезжали» с карточек. Слот ищется линейным поиском по `field.slots`.
  Неоновую обводку получают **только крыши**: у текстовых блоков рамка не
  совпадает ни с чем видимым, а у наклонённого баннера `getBoundingClientRect`
  отдаёт габаритный прямоугольник заметно больше самой карточки.
- `defs.ts` — баланс: цены, урон, HP, апгрейды, экономика. **100 волн**: первые
  девять расписаны руками (знакомят с типами по одному), дальше генерируются
  `waveOf` — численность растёт и обычным множителем, и линейной прибавкой
  `+5 особей за волну`. **Численность волны никогда не убывает**: волны
  строятся по порядку с памятью о предыдущей, недобор добивается мелочью
  (`waveOf` + кэш). Просадки возникали сами собой — и в ручной таблице, и
  после каждой босс-волны, — а читаются игроком как «стало легче», хотя
  враги при этом только крепчают. Суммарный HP после босс-волны падать
  может, и это намеренно: босс — пик, за ним передышка. Каждая десятая — босс-волна со своим «страшным»
  банковским именем (`bossTitle`: от «ТЕХНИЧЕСКИЙ СБОЙ» до «НАЧАЛЬНИК ПРИШЁЛ»),
  боссов в ней `номер / 10`, и **каждый босс обесточивает одну случайную башню
  до конца волны**.
- **Апгрейды** — по два уровня на башню, каждый усиливает её собственную роль
  (`UPGRADES` + `statsOf`). Панель открывается кликом по поставленной башне,
  там же продажа. Уровень хранится в `tower.lvl`, а `tower.st` — уже
  посчитанные характеристики: боевой код читает только `st`, не `def`.
  Уровень видно на поле сразу тремя способами: светящееся кольцо под подошвой,
  шевроны над макушкой (по одному за уровень) и ореол вокруг корпуса на втором.
- `game.ts` — симуляция и отрисовка. Статика (обводки зданий, сетка, маршруты) печётся
  в offscreen и блитится одним `drawImage`; каждый кадр рисуются только живые объекты.

На карточке в колоде под описанием — строка характеристик со значками
(`statChips`): ⚔︎ урон в секунду, ≫ темп, ◎ дальность и то особенное, что есть у
этой башни (◌ осколки, ⌁ цепь, ≋ поджиг, ❄︎ замедление); расшифровка каждой в
`title`. Урон показан именно В СЕКУНДУ: у огнемёта «за выстрел» стоит 3,6 при
восьми тиках в секунду, и сравнивать башни по этому числу невозможно.

Управление: 1–5 или карточки — выбор башни, ЛКМ — поставить, **клик по башне —
панель улучшения/продажи**, **перетаскивание башни в колоду (или ПКМ по ней) —
продать за 50% вложенного**, Пробел — вызвать волну раньше (премия за каждую
сэкономленную секунду), P — пауза, F — 1×/2×. Кнопка **⟲ в HUD перезапускает
партию в два клика**: первый взводит её на три секунды, второй сносит —
случайный промах по HUD не должен стирать оборону.
Звук синтезируется на WebAudio — **файлов в репо нет**.

**Экономика собрана вокруг дефицита денег.** Награда за голову низкая и почти не
растёт с волной (`bountyMul` +1,2%/волна) — доход увеличивается сам собой, потому
что врагов становится больше. **Цена башни постоянна** и не зависит от того,
сколько их уже стоит: прыгающий ценник в колоде читался как ошибка. Денежный
сток — апгрейды. Возврат считается от фактически вложенного
(`tower.paid`, включая апгрейды). Новая башня и апгрейд намеренно сопоставимы по
цене: полная прокачка стоит примерно как две-три новых башни — на этом и держится
выбор, куда потратить.

**Обгон на маршруте.** Враги идут по общей дорожке, но у каждого своя полоса
(`lane`, ±15px от осевой). Догнавшего НЕ упирают в спину переднему — иначе
быстрая «Пеня» вставала в очередь за «Налогом» и вся её скорость пропадала.
Дистанцию держат только равные по скорости (аккуратная колонна), а при разной
скорости оба сдвигаются вбок и разъезжаются; после обгона полоса плавно
возвращается к своей (`lane0`).

Счётчик в HUD — «ОСТАЛОСЬ»: невыпущенные плюс живые из ВОЛНЫ, а не то, что
видно на экране сейчас; в паузе между волнами показывает состав следующей.

Слева над колодой — **сворачиваемый бестиарий** (HP, скорость, броня, сколько уносит
со счёта); при первом появлении типа врага он объявляется отдельным тостом и строка в
бестиарии подсвечивается.

Поле пересобирается на `resize`; башни на исчезнувших крышах снимаются. Скролл борда
на время партии заблокирован (`body.td-armed`), поле считается по видимому кадру.

> **Важно про геометрию.** Поле — снимок DOM, и любой сдвиг раскладки ПОСЛЕ съёмки
> оставлял бы его протухшим навсегда: зоны и обводки поехали бы относительно
> карточек. Поэтому съёмка не разовая:
> 1. старт откладывается, пока `.content` не перестанет менять rect (4 кадра
>    подряд, предохранитель ~1.5s) — панель tools закрывается с анимацией;
> 2. дальше работает **сторож** (250мс): сверяет якорь (первый баннер) с DOM и
>    при расхождении больше 6px пересобирает поле. Ловит не только ресайз, но и
>    доехавший шрифт, появившийся скроллбар, любую внешнюю анимацию.
>
> Сторож **молчит, пока борд трясётся** (`body.td-hit`). Тряска — это transform
> на `.board`, а трансформ предка сдвигает clientRect всех блоков внутри на
> ±6px. Без этой оговорки сторож принимал тряску за поехавшую раскладку и
> пересобирал поле прямо посреди анимации: на волнах с частыми прорывами башни
> перескакивали на соседние места.
>
> При пересборке башни переносятся **по id слота**, а не по координатам: нарезка
> слотов детерминирована (порядок обхода DOM), поэтому при неизменном наборе крыш
> башня переезжает вместе со своей карточкой.

## Подводные камни

- **StrictMode (dev)** дважды прогоняет эффекты — во всех хуках сделан строгий cleanup
  (снятие слушателей, `clearTimeout/Interval`, `cancelAnimationFrame`). `tasksFinal` в хуках
  задач захардкожен, иначе второй прогон читает уже очищенный DOM.
- **`React.memo` на MainV1/MainV2 обязателен** — иначе апдейт контекста перерисовывает их и
  `dangerouslySetInnerHTML` пере-инжектит статику, стирая JS-выставленные стили (top'ы стека).
- **Не запускать `next build` при живом `next dev`** — общий `.next` ломается
  (`Cannot find module './694.js'`); лечится `rm -rf .next` + рестарт dev.
- **Fast Refresh** ругается на смену числа хуков «на горячую» — помогает полный рестарт dev.
- **Оверлеи** (`.nbar/.spot/.chat/.twk`, `.board`) — вне трансформируемого контента (у fixed
  внутри `transform`-предка ломается позиционирование); neuro-обёртка — `display:contents`.
